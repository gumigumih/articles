# note記事カバー画像

一般note記事のタイトルと主題から、リポジトリの既定プロンプトに沿ったカバープロンプトを作成し、ユーザーが明示的に画像生成を依頼した場合だけカバー画像を生成・反映する。

## 使うとき

- note記事のカバー画像プロンプトを作成するとき
- 「カバー画像を作って」「プロンプトを使ってカバーを作って」と依頼されたとき
- 既存カバーを確認し、記事の色使いや画像参照を整えるとき

記事本文の執筆、タイトル設計、noteへの投稿、コミット、pushはこのスキルの対象外とする。

## 参照する正本

最初に、対象リポジトリの次を読む。

1. `AGENTS/README.md`
2. `AGENTS/platforms/README.md`
3. note記事の場合は`AGENTS/platforms/note/README.md`
4. `AGENTS/common/image.md`

カバープロンプトの出発点は、必ず`AGENTS/common/image.md`の「note記事カバーの既定プロンプト」を使う。ユーザーが別のデザイン、色、参照画像、文字量を指定した場合だけ、その指示を優先する。

## 入力の確認

対象記事のMarkdownから次を確認する。

- フロントマターの`title`
- 記事本文の主題
- 記事スラッグと保存先
- 既存のカバー画像、本文画像、色使い
- IP名、キャラクター名、個人情報、内部URL・IDなどの公開制限

タイトルが未確定、対象記事が複数、または匿名化範囲が不明な場合は、勝手に補わず確認する。

## プロンプトの作成

`AGENTS/common/image.md`の既定プロンプトへ、次を差し込む。

- `{{記事タイトルを正確に記載}}`：記事のタイトルを一字一句そのまま入れる
- `{{内容に合う小さな図形・アイコンの案}}`：本文にある事実だけから、人物・固有IP・キャラクターに依存しない小さな図形やアイコンを短く指定する

既定プロンプトの次の条件を削除・弱めない。

- タイトルを最前面に大きく配置する
- タイトル以外の文字を入れない
- 文字を省略・追加せず、端で切らない
- 黒を基調に、白・マゼンタの文字、シアン・黄色のアクセントを使う
- 参照画像を使わない
- 人物・キャラクター・顔・動物・ロボットを描かない
- ロゴ、透かし、号数、日付、連載名を入れない

完成したプロンプトは、記事と同じスラッグの次のファイルへ保存する。

`note/<記事スラッグ>.cover-prompt.md`

この付属ファイルには本文用のフロントマターや`note_id`を付けない。プロンプト内へ個人情報、認証情報、非公開URL、内部IDを入れない。

## 画像生成

画像生成は、ユーザーが明示的に依頼した場合だけ行う。

1. `imagegen`スキルを使い、既定プロンプトをもとに新規画像を生成する
2. 既存画像を上書きせず、まず新しい候補として保存する
3. 生成画像を目視確認する
4. タイトルの誤字・欠落、文字切れ、縮小時の可読性、意図しない人物・キャラクター、過度なドットやざらつきを確認する
5. 問題があれば、一度に一つの修正だけを指定して再生成する

プロジェクトへ保存する最終画像は、記事専用ディレクトリの次の場所を基本とする。

`note/images/<記事スラッグ>/cover.png`

すでに`cover.png`がある場合は、勝手に上書きせず`cover-v2.png`などの別名で保存し、採用するファイルをユーザーに確認するか、ユーザーが差し替えを依頼している場合だけ本文リンクを更新する。

## 本文への反映

ユーザーが記事への反映まで依頼した場合は、フロントマター直後、H1タイトルの直前に次を置く。

```markdown
![CoverImage](images/<記事スラッグ>/cover.png)
```

既存のカバー画像参照がある場合は、相対パスと実ファイルの存在を確認してから更新する。画像生成だけの依頼では、本文を変更しない。

## 完了確認

- `.cover-prompt.md`が対象記事のスラッグで保存されている
- 画像を生成した場合、画像が`note/images/<記事スラッグ>/`に保存されている
- 本文へ反映した場合、相対パスが正しく、画像ファイルが存在する
- タイトル、匿名化範囲、記事本文の事実を変更していない
- `git diff --check`でMarkdownの問題がない
- コミット、push、noteへの投稿をしていない

生成画像のサービス風アイコンやロゴが公式のものか、note上での最終表示が正しいかは、別途確認が必要である。検索ボリュームや公開状態を推測して完了扱いにしない。
