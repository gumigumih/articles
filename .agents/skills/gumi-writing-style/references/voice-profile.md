# ぐみ文体プロファイル

根拠は、リポジトリ内の既存noteです。「AIとわたしの深夜エンタメ会議」#1〜#4に加え、AIの実務考察、個人開発、ディレクションのノウハウ、制作の振り返りを確認したうえでまとめています。これは文体上の傾向であり、すべての記事へ一律に適用する規則ではありません。

## 共通する話し方

- 冒頭は「こんばんは、ぐみです。」のように短く入る。
- 自分が引っかかった場面、困った場面、試した場面から話を始める。
- 技術や仕事の話も、読者と一緒に「これってどうなんだろう」と眺める距離感を取る。
- 判断は持つが、結論を押しつけず、読者の実感へ戻して終える。
- 一文を長く説明し続けず、短い段落と問いで読みの呼吸を作る。

## よく使うリズム

| 働き | 言い方の例 |
| --- | --- |
| 小さな引っかかり | ちょっと、つい、けっこう |
| 自分の判断 | やっぱり、気がします、と思っています |
| 読者への共有 | 〜なんですよね、〜ですよね、〜してみたい |
| 軽い省略 | だけじゃなく、〜ちゃう、〜なってる |

「ちょっと」「やっぱり」は、それ自体を個性にしない。読み手の注意を寄せたい一文にだけ使う。

## 記事種別で変わる明るさ

| 記事種別 | 文体の温度 | 使える要素 |
| --- | --- | --- |
| 深夜エンタメ会議 | 静かで少しお茶目 | 「つい」「じわっと」「〜なんですよね」、読者への小さな問い |
| AI・仕事の振り返り | 率直で共感寄り | 「正直」「〜って」「〜じゃん」、困りごとからの導入 |
| 実務ノウハウ・個人開発 | 明るく伴走する | 「ありませんか？」「〜なんです」「シェアしちゃいます！」、必要に応じた感嘆符 |
| 仕様・手順・注意 | 落ち着いて明確 | 省略せず、主語・条件・数値を残す |

絵文字と感嘆符は、既存の実務ノウハウ記事では使われている一方、現在のマガジン記事では使わない。記事に近い型を優先する。

## 既存記事に見られる型

- 「派手な完成画面に、つい目を奪われます。」
- 「これが企画会議で見せられる試作になったら、かなり強いですよね。」
- 「『検閲を避けたいから』だけじゃなく、データを外に出さない選択肢として眺めたい公開でした。」
- 「値下げのあいだに利用者を集めて、通常価格に戻っても続けたくなる体験まで作れるか。」
- 「正直、『〇〇エンジニアリング』、増えすぎ問題だと思っています😅」
- 「そんな経験、ありませんか？」
- 「今回は、その実体験から学んだ『未経験分野のディレクションを行う3つのコツ』をシェアしちゃいます！」

型をそのまま繰り返さず、扱う対象に合わせて使う。

## Zennでの語り方

`zenn/articles/20260302_vibe-coding-rebuild.md` は、困った場面から具体的な設計・運用判断へ進む説明の例。`zenn/articles/20260826_ai-engineering-terms-too-many.md` は、自分の疑問から概念を整理し、実務上の判断へ戻す語り方の例です。どちらもリポジトリルートからのパスです。

「私の場合」「ここで困ったのは」「実際に試すと」で観察の対象を具体化します。感想は柔らかく、手順・仕様・制約は明確に書きます。既存記事は文体の資料であり、技術的主張をそのまま新しい記事の根拠にせず、強い語調や見出し形式も一律には移植しません。

## 適用の境界

- 製品仕様、価格、日付、投稿者による利用報告、法的・権利上の注意は敬体で簡潔に書く。
- 「〜ちゃう」「〜なんですよね」は、事実の確度を下げる目的では使わない。
- 口語を一段落に複数重ねない。記事の地の文が軽くなりすぎるのを防ぐ。
