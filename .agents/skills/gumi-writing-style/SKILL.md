# ぐみ文体

ぐみ名義のnote・Zenn記事を、事実を大切にしながら親しみやすく書くためのスキルです。既存記事で見える語り方を根拠に、媒体と記事の目的に合わせて説明の厚みを変えます。文体模倣を、出自偽装やAI検出器回避の目的には使いません。

## 使うとき

- ぐみ名義のnote・Zenn記事を新しく書く、または推敲するとき
- 「いつもの文体」「フレンドリー」「お茶目」「人間らしく」など、既存記事に寄せる依頼があるとき

事実確認、出所の追加、権利判断、媒体固有の構成設計が主目的なら、それぞれの作業を先に行い、文体調整は最後に行います。

## 媒体に合わせる

- **note**：本人の動機・迷い・驚き・変化を追い、体験の流れを中心にする。
- **Zenn**：読者が自分の開発や判断に持ち帰れるよう、前提・手順・判断理由・結果を具体的に伝える。実践記事では必要な入力・添付物・事前状態を補い、設計考察では選択肢と適用条件を示す。記事にないコードや実装例は創作しない。

両媒体に展開するときは、それぞれの本文だけで話が通るようにする。同じ画像や事実の再利用は問題ない。ユーザーが残したプロンプトや体験を重複解消だけのために削らず、Zennでは判断基準や各指示の役割を厚くする。

公開形式はリポジトリの `AGENTS/platforms/`、内容・出所のレビューは記事種別に対応するチェック用スキルに従う。文体調整だけを理由に公開設定を変えない。

## 記事ごとの温度を選ぶ

- **深夜エンタメ会議・ニュース考察**: 静かで親しい敬体。感想は「〜なんですよね」「〜かな、と思います」で置く。絵文字や感嘆符は原則使わない。
- **実務ノウハウ・個人開発**: 読者の困りごとから入り、会話するように説明する。「ありませんか？」「〜なんです」「〜してみました！」を必要な箇所だけに使える。
- **個人的な振り返り・エッセイ**: 短い段落を重ね、身体感覚やその場で起きた小さな気づきから考えを進める。

依頼された記事に近い既存記事を優先し、別ジャンルの明るさをそのまま移植しない。

## 文体の核

- 事実説明は落ち着いた敬体で、感想・つなぎ・まとめだけを少しくだけさせる。
- 「ちょっと」「けっこう」「つい」「やっぱり」「じわっと」を、気持ちが動く箇所にだけ使う。段落ごとに散らさない。
- 「〜なんですよね」「〜気がします」「〜かな、と思います」「〜してみたい」を使い、結論を読者へ押しつけずに置く。
- 「だけじゃなく」「〜ちゃう」「〜なってる」のような省略は、話者の感想・観察に限定する。仕様、数字、引用、出所、注意書きでは使わない。
- 小さい「っ」のある言葉はリズムを作るために使うが、同じ段落で重ねない。
- 断定を弱めるためだけの「かもしれません」は多用しない。根拠がある観察は普通に言い切り、未確認事項だけを明示する。

## 書き換え方

1. URL、引用、固有名詞、数値、日付、出所区分、注意書きを保護する。
2. 各節で、事実・ぐみの感想・推測・読者向け提案を区別する。省略・要約した指示は明示し、新しく作ったテンプレートを実行ログとして見せない。
3. 説明文が連続する箇所では、必要に応じて短い観察や読者への軽い問いを置く。各節へ機械的に足さない。
4. 「重要です」「必要です」「〜を示します」のような説明資料の語を、記事の文脈で自然な述語へ直す。ただし義務や安全上の注意は変えない。
5. 最後に、全段落を同じテンポへそろえすぎていないか確認する。

## 避けること

- 新しい事実、体験談、感情、比喩を足さない。
- 全文を砕けた口調にしない。投稿の要約と根拠の説明は、読み手が確認できる言葉で書く。
- 「笑」「w」や過度な絵文字でお茶目さを足さない。
- 「〜っぽい」を、根拠をぼかすために使わない。
- 一度の成功を一般的な性能保証や確定した因果関係に広げない。
- 読者を初心者と決めつけない。専門用語は理解に必要なものだけ短く説明する。
- レビューだけの依頼では本文を変更しない。
