# 記事内の表をGistで管理する

このプロジェクトの `note/**/*.md` にあるMarkdown表を対象にする。表の抽出、Gist用Markdownの整形、既存Gistとの差分確認、記事へのGist URLコメントの追加・更新・削除を支援する。

## 基本方針

- 記事本文の表そのものは保持する。外部リンクへの置換は、ユーザーが明示した場合だけ行う。
- GitHub Gistの作成・更新・削除と記事ファイルの変更は、実行直前に対象・内容・公開範囲を提示し、ユーザーの明示承認を得てから行う。
- Gistの認証は、既存のGitHub CLI認証を使う。PATをファイルへ保存したり、トークンの値を表示したりしない。
- `.gitignore` 対象の `gist.config.json` や `gist-records.json` は読まない。既存Gistの特定には、記事内の `Gist埋め込み用URL` コメントか、ユーザーが提示したGist URLを使う。
- Gistの作成・更新後も、記事のコミット、push、note・Xへの投稿は自動で行わない。

## 手順

### 1. 対象と表を確認する

1. 対象は `note/` 配下のMarkdownに限定する。パスが曖昧なら候補を提示する。
2. Markdownのコードフェンス内は表として扱わない。
3. `|` で構成されたヘッダー行と区切り行を含む連続したMarkdown表を抽出する。
4. 表の直前にある見出し（`##`〜`####`）を表題として使い、見出しがなければ `表1`、`表2` のように仮名を付ける。
5. 各表について、記事パス、行番号、表題、抽出内容、既存のGist URLコメントの有無を整理する。

### 2. 実行前プレビューを出す

作成・更新・削除の前に、少なくとも次を示す。

- 対象記事と対象表
- 作成・更新・削除の別
- Gistのファイル名と説明文
- 公開または非公開の別
- 記事に追加・更新・削除するコメント
- 既存Gistを更新する場合のGist IDまたはURL

公開範囲が指定されていない場合は、勝手に公開Gistを作らず確認する。記事から参照する公開Gistが必要な場合も、その理由を説明する。

### 3. 認証とGist操作

実行前に `gh auth status` でGitHub CLIのログイン状態だけ確認する。認証情報の値は取得・表示しない。

Gist APIを使う場合は、表の内容を一時ファイルに保存して `jq --rawfile` でJSON化し、`gh api` に渡す。シェル引数へ表本文を直接埋め込まない。

- 作成: `POST /gists`
- 更新: ユーザー指定または記事コメントから特定できたGist IDへの `PATCH /gists/{id}`
- 削除: ユーザーが明示したGist IDまたはURLに対する `DELETE /gists/{id}` のみ

Gist操作が成功したことをAPIレスポンスで確認してから、記事内の次の形式のコメントを追加・更新する。

```markdown
<!-- Gist埋め込み用URL: https://gist.github.com/... -->
```

記事内の既存コメントを更新する場合は、表の直後にあるコメントだけを対象にする。表の内容や他のコメントを巻き込まない。

### 4. 終了時の確認

- 作成・更新後のGist URLと公開範囲
- 記事ファイルの変更差分
- 表の数と、各表の処理結果
- 未処理の表や失敗した操作

を報告する。ユーザーが求めない限り、コミットやpushは実行しない。

## 削除時の注意

削除は作成・更新より慎重に扱う。記事名だけを根拠にGistを一括削除せず、対象URLまたはIDを一つずつ確認する。Gist削除に失敗した場合は記事内コメントを削除しない。
