# 執筆委譲の共通ルール

## 目的

このファイルは、マガジン記事・一般記事・お知らせ記事を文章化するときの共通ルールです。
記事の内容や媒体固有の構成は各ルールファイルで定め、執筆担当の役割境界と受け渡し方法はここで統一します。

## 適用範囲

- `note/` 配下のマガジン記事、一般記事、お知らせ記事
- ChatGPT/Codexが作成した調査・分析メモをもとにした本文初稿
- 標準のClaude Desktop、または必要に応じてユーザーが選択するClaude Code CLI

## 役割分担

- ChatGPT/Codex: 候補の調査、事実確認、出所の整理、分析、候補選定、構成案の提示
- 文章化担当: 承認済みの候補・構成・調査メモを、媒体固有ルールに沿って本文へ整える
- ユーザー: 候補・構成の選択、最終レビュー、画像生成、note/Xへの投稿、公開時期の決定、Git操作

文章化担当は、調査・分析担当の代わりに判断を広げません。入力にない事実、独自のWeb検索、独自の事業性・UX・技術評価を追加しないでください。

## 執筆前の確認

1. ルートの`AGENTS.md`と、対象媒体に関係する`AGENTS/`配下のルールを読む。
2. 承認済みの候補・構成・調査メモだけを執筆材料として扱う。
3. 本人の実体験・発言・判断、他人の相談・意見・引用、一般論、AIによる推測を区別する。
4. 出所や公開可否が確認できない情報は、本人の体験や確定事実として書かない。
5. 直近記事を確認し、タイトル・主張・構成の重複を必要な範囲で避ける。

## 共通の文章化ルール

- 入力資料にある事実だけを使い、足りない情報は「要確認」と明記する。
- 他人の相談・意見・引用を、ユーザー本人の一人称の体験談へ変換しない。
- 構想、PoC、実装済み、運用中、公開済みを混同しない。
- 数字、固有名詞、効果、原因、将来予測は、入力資料の根拠がある範囲で表現する。
- 媒体固有の読者、文体、構成、フロントマター、画像・リンクルールを優先する。
- 不自然な誇張や、根拠のない成功談・失敗談を補わない。
- 本文以外の成果物は、媒体固有ルールまたは今回の依頼で指定されたものだけ作る。

## 本文ファイルの境界

- `note/{記事スラッグ}.md`には、フロントマター、カバー画像の参照またはTODO、記事本文、本文中のリンク・埋め込み、参考リンクだけを置く。
- カバー画像生成用プロンプト、X投稿文、調査メモ、編集メモ、チェック結果、作業報告は本文ファイルへ追記しない。
- 付属成果物は用途ごとに別ファイルへ保存する。マガジン記事のX投稿文は`note/{記事スラッグ}.x-post.md`、カバー画像プロンプトは`note/{記事スラッグ}.cover-prompt.md`とする。

## 媒体別の受け渡し条件

### AIとわたしの深夜エンタメ会議

- `topics/*-candidates.md`で「推奨」「採用」と明記された候補と、そこにある調査・分析メモを受け取ってから文章化する。
- `AGENTS/monetization.md`と`AGENTS/weekly-ai-note-prompt.md`を媒体固有ルールとして適用する。
- 無料・有料の構成、カバー画像プロンプト、X投稿文下書きはマガジン固有ルールに従い、本文ファイルとは分けて保存する。

### 一般note記事・ブログ記事

- ユーザーが候補と構成を選択してから文章化する。
- `AGENTS/general-note.md`を媒体固有ルールとして適用する。
- 本人由来でない内容は、観察・分析・紹介など、確認できる出所に合った記事形式にする。

### マガジンのお知らせ記事

- `topics/*-monthly-analysis.md`の分析メモを唯一の調査・分析材料として扱う。
- 記事の主題、数値、比較期間、仮説の確度を分析メモから逸脱させない。

## 実行環境とスケジュールの境界

- Claude Desktopを標準の文章化環境とし、必要に応じてClaude Code CLIも利用できる。
- どの環境を使うか、どの画面・コマンドから起動するかは、スケジュールではなくこの共通ルールと個別の執筆依頼で扱う。
- 定期スケジュールは、調査・分析メモの作成と受け渡しまでを担当し、特定のClaude製品、CLI、スクリプト、起動方法を埋め込まない。
- Claude DesktopまたはClaude Code CLIへの入力では、対象記事に必要な資料だけを渡し、秘密情報や公開不可の実データを含めない。
- Anthropic側の利用料金が発生・増加する可能性がある。対象環境は、ユーザーが選択したClaude Desktopまたはローカル実行のClaude Code CLIとする。

### Claude Desktopで執筆する場合

1. 対象記事の候補・構成・調査メモと、このリポジトリの`AGENTS/`配下の関連ルールをClaude Desktopに渡す。
2. 媒体固有の執筆ルールに従って、本文初稿を`note/`配下へ保存する。
3. 保存後に、対象ファイルのパスと実行結果を報告する。

### Claude Code CLIで執筆する場合

1. スケジュールから自動起動せず、候補・構成の承認後にリポジトリでCLIを対話的に起動する。

   ```sh
   cd /Users/meggumi/Github/gumigumih/articles
   claude
   ```

2. 起動後の依頼で、入力に使う候補・分析メモ、保存する記事のパス、媒体固有ルールを明示する。
3. 一般記事では、候補・構成・必要な事実確認事項を個別に渡し、`AGENTS/general-note.md`と共通ルールを読ませる。候補選択・構成選択をCLIに代行させない。
4. 実行前に、Anthropic側の利用料金が発生・増加する可能性と、ローカルCLI実行であることを確認する。

## 執筆後の確認

- 対象ファイルが指定の`note/`配下に保存されている。
- 本文ファイルに、カバー画像プロンプト、X投稿文、調査・編集メモなどの付属成果物が混在していない。
- 本文以外のファイルを、依頼なく新規作成・変更していない。
- 出所、公開可否、要確認事項が保持されている。
- 媒体固有のセルフチェックを実施し、必要な修正を反映している。
- 本文の新規作成または内容を変える改稿の完了前に、記事全体を次の二段でチェックする。
  1. `natural-japanese`で、自然さ・読みやすさ・論旨を確認する。通常はクイックモードでlintとスケルトン通読を行い、公開前の入念な確認やユーザーが求めた場合はフルモードでlint、outline、terms、構造・読みやすさ・文書タイプのレビューまで行う。
  2. `$geonwoo-jeong:japanese-humanizer`で、翻訳調、機械的な均質さ、冗長表現、係り受け、抽象的な締めを診断する。長文または監査では`profile-japanese-text.mjs`も使う。
- 両方の検出結果は修正候補であり、自動で本文を書き換えない。URL、引用、数値、固有名詞、専門用語、条件、否定、責任主体を保護し、意味や出所を変えないことを人が確認してから修正する。
- 文章の自然さを理由に、AI検出器の回避や著者の出自偽装を目的とした修正は行わない。
- note/Xへの投稿、画像生成、コミット、pushは行わず、対象ファイルのパスと結果だけを報告する。
