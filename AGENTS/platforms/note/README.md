# noteルール

## 適用対象

`note/`配下の本文記事に適用します。`*.x-post.md`、`*.cover-prompt.md`、調査メモなどの付属ファイルには、本文用のフロントマターや`note_id`を付けません。一般記事は`general-note.md`、有料マガジン「AIとわたしの深夜エンタメ会議」は`AGENTS/magazines/ai-entertainment/article.md`を追加で読みます。

## 読む順番

1. `AGENTS/common/writing-workflow.md`
2. このファイル
3. `AGENTS/platforms/note/general-note.md`またはマガジン固有ルール
4. `AGENTS/common/quality.md`、`AGENTS/common/structure.md`、`AGENTS/common/link.md`、`AGENTS/common/image.md`のうち作業に必要なもの

## 読者と記事の方向性

- 対象: PM、ディレクター、非エンジニア層、個人の経験や考察を読みたい人
- 内容: キャリア視点、体験談、仕事術、制作・利用の観察
- 構成: 読み物としてのストーリーと、読者が持ち帰れる気づき
- 目的: 経験の共有と共感の獲得

## フロントマター

```yaml
---
title: "記事タイトル"
note_hashtags: "#タグ1 #タグ2 #タグ3 #タグ4 #タグ5"
date: YYYY-MM-DD
note_id: "nxxxxxxxxxxxx"
---
```

- `title`: 記事タイトル。ダブルクォートで囲む。
- `note_hashtags`: note投稿用のハッシュタグ。`#`付きでスペース区切り、原則3〜5個程度、必要な場合でも7個以内にする。タイトルと本文にある中心語を優先し、本文にない流行語、検索されそうというだけの類語、広すぎる親タグで水増ししない。スペースを含む製品名などは、note上で検索対象にしたい表記を損なわない範囲で、プラットフォームが扱える一続きの表記にする。
- `date`: 公開日または記事の日付が確定している場合に記載する。未確定の下書きでは推測で入れない。
- `note_id`: 下書き保存後は、実際の編集画面URLに含まれる下書きIDを自動記録する。公開後は公開URLにある`/n/<id>`を確認し、公開用のIDへ更新する。URLに存在しないIDを推測して記載しない。
- `note_id`はファイル名、公開日、タイトルから生成しない。ID lookupと公開状態の確認を分ける。
- 本文をnoteへコピーするときは、note上ではフロントマターを外す。リポジトリの原稿には、後から公開状態と`note_id`を追跡できるようフロントマターを残す。
- 公開前にnoteの公開設定画面を開き、原稿の`note_hashtags`と実際に選択されているタグが一致するか確認する。本文中のカラーコードや固有名詞の一部が自動候補として選択される場合があるため、自動候補をそのまま採用しない。

## note固有の埋め込み

noteで埋め込み表示にしたいURLは、次の記法で囲みます。通常リンク、参考リンク、本文中のテキストリンクには使いません。

```text
<!-- note:embed -->
https://x.com/example/status/123
<!-- /note:embed -->
```

埋め込みに対応しないURLは、通常リンクとして残します。X投稿は、投稿者による試行・反応と公式情報を区別して扱い、製品仕様や商用導入の根拠にしません。

## Markdown表の扱い

- note本文ではMarkdownのパイプ表が表として表示されないため、記事の読者向け表示にそのまま使わない。
- 記事のMarkdown原稿では表の構造と内容を維持し、箇条書きなどへ組み替えない。noteへ載せるときは、表をそのまま画像化するかGist化する。
- 既定は表の可読性を保った画像化とし、横幅・行数が多く画像では読みづらい表はGistを使う。画像はMarkdown表を忠実にレンダリングし、画像生成モデルで表を描き直さない。
- 画像化した表は記事用画像として保存し、本文の表と差し替える際も元のMarkdown表はリポジトリ内に残す。Gistの作成・更新・削除と記事へのリンク反映は`article-table-gist`の手順と承認境界に従う。
- note下書き作成・更新前にMarkdown表を検出し、対応する画像または承認済みGistへ置き換えてから反映する。変換に必要な素材・読みやすさの判断に不足があれば、保存前に確認する。

## 文体

- です・ます調を基本にし、会話的なくだけた表現も使える。
- 一人称は「私」または「ぐみ」。体験談・気づきは本人の出所が確認できる範囲で書く。
- 読者への語りかけと共感を重視する。
- 専門用語は初出で短く説明し、一般読者が場面を思い浮かべられる表現を優先する。
- 絵文字・顔文字は記事のトーンに合う範囲で使う。
